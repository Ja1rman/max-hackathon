# API сервиса «За столом»

Полная машиночитаемая схема находится в [openapi.yaml](../openapi.yaml). Production base URL: `https://mail.lonelycraft.ru/banquet`. Запросы с JSON отправляйте с `Content-Type: application/json`; все цены и суммы передаются **в целых копейках**, даты — ISO 8601 с часовым поясом. Ошибки имеют вид `{"error":"..."}`. Идентификаторы берите из ответов API.

## Вход и роли

В Mini App передайте исходную строку `window.WebApp.initData` в `POST /api/auth/max`:

```json
{"initData":"<строка MAX Bridge>"}
```

Ответ содержит `token` сервиса и `user`. Во всех защищённых запросах используйте `Authorization: Bearer <token сервиса>`. **Токен бота MAX для этого не подходит и никогда не отправляется из браузера.** Для локальной проверки можно войти через `POST /api/auth/demo` с `{"role":"organizer"}`; демо-данные изолированы и не имеют доступа к реальным банкетам.

Роль `restaurant` задаётся серверным списком `RESTAURANT_ADMIN_IDS` по проверенному MAX user ID. Остальные MAX-пользователи имеют роль `organizer`, но могут участвовать в банкете как гости. Создавать и администрировать банкет может владелец или роль `restaurant`; **утвердить заказ может только владелец**. Общий каталог ресторана редактирует только роль `restaurant`.

## Создание банкета и список гостей

1. `GET /api/restaurants` — получить рестораны и их текущий каталог.
2. `POST /api/events` — создать банкет. Тело: `restaurantId`, `title`, `date`, `deadline`, `expectedGuests`, необязательный `guestBudget` — бюджет на одного гостя в копейках (0 — без ограничения). Сервер создаёт снимок доступных блюд.
3. `PATCH /api/events/{eventId}` — изменить название, дату, срок выбора, число гостей или `guestBudget`. Передайте `expectedRevision` из последнего `GET /api/events/{eventId}`. При устаревшей ревизии получите `409` и должны перечитать данные.
4. `POST /api/events/{eventId}/guests` с `{"name":"Анна","phone":"+7 999 123-45-67"}` — добавить гостя. `PATCH` и `DELETE /api/events/{eventId}/guests/{guestId}` — изменить или удалить запись. Телефон нельзя поменять после привязки к MAX; гостя с сохранённым выбором удалить нельзя.
5. `GET /api/events/{eventId}` — владельцу и ресторану вернёт `invitedGuests`, `guests`, `summary` и ссылки приглашения. Телефоны не включены в публичный просмотр по ссылке и в ответ чужому гостю.

Число гостей — ориентир для интерфейса; при добавлении записи список может увеличить `expectedGuests`. Все изменения разрешены до утверждения. После утверждения состав заказа фиксируется. Для приглашённых live-банкетов важен **список с телефонами**: ссылка только открывает банкет и не даёт права выбрать чужие блюда.

## Подтверждение гостя и заказ

Гость входит через MAX и запускает `window.WebApp.requestContact()` по нажатию кнопки. Результат `{phone, authDate, hash}` передаётся в `PUT /api/me/phone`. Сервер проверяет подпись MAX с токеном бота и связывает номер с проверенным MAX ID из сессии. Подменить `userId` параметром запроса нельзя. Если Mini App открыт **общей кнопкой бота** и код банкета отсутствует, вызовите `POST /api/me/claim-invitations` с пустым телом: сервер найдёт записи **этого подтверждённого номера** во всех открытых банкетах, закрепит их за текущим MAX ID и вернёт `{ "eventIds": [...] }`. Запрос безопасно повторять, в том числе при следующем входе: новые приглашения тоже появятся. При персональной ссылке остаётся `POST /api/invites/{code}/join`. Один номер не может быть привязан к двум аккаунтам; одна запись банкета не может принадлежать двум гостям.

`GET /api/events/{eventId}` возвращает меню, `canSelect` и собственный `selection`. `PUT /api/events/{eventId}/selection` полностью заменяет выбор текущего пользователя:

```json
{
  "items": [{"menuItemId":"dish_...","quantity":2}],
  "notes":"Без орехов"
}
```

Цена и сумма вычисляются сервером из меню банкета. Если сумма выбора больше `event.guestBudget`, сервер вернёт `409`. Позиции с `forGuests: false` и позиции общего стола выбрать нельзя (`400`). Гость не может передать ID другого пользователя. После дедлайна или утверждения изменения блокируются. `POST /api/events/{eventId}/approve` с `{"expectedRevision":12}` утверждает текущую версию. Для кухни доступны `GET /api/events/{eventId}/export.csv` и одноразовая ссылка `POST /api/events/{eventId}/export-link`.

## Меню банкета и общий стол

Меню банкета — снимок каталога. У каждой позиции есть флаг `forGuests`: `PATCH /api/events/{eventId}/menu/{itemId}` с `{"forGuests":false}` скрывает её от гостей (гостям такие позиции не отдаются). Позицию, которую уже выбрал гость, скрыть нельзя. `POST /api/events/{eventId}/menu/import` с `{"itemIds":["dish_..."]}` добавляет позиции каталога ресторана, которых ещё нет в банкете.

`PUT /api/events/{eventId}/shared` задаёт общий стол целиком:

```json
{"items": [{"menuItemId":"dish_...","quantity":3}]}
```

Позиции общего стола входят в `event.total` и сводку кухни, но не в бюджет гостя. Гости видят их в `detail.shared` и не могут заказать сами. Позицию, которую уже заказал гость, на общий стол перенести нельзя.

## Внутренняя валюта гостя

API всегда работает в копейках; пересчёт делает интерфейс гостя (`shared/currency.mjs`): еда — кусочки пирога по 10 ₽, позиции категории «Напитки» — бутылочки по 100 ₽, дробные значения не округляются до целых. Бюджет гостя показывается в обеих единицах, потраченное — отдельно по еде и напиткам.

## Администратор и кухня

Роль `restaurant` — администратор ресторана. `GET /api/kitchen` возвращает все банкеты пространства с датой не раньше вчерашнего дня: `event` (с `ownerName`), порции `summary` с учётом общего стола, `shared` и гостей с выбором, пожеланиями и местом. Владелец и администратор также получают `event.ownerName`, `event.sharedTotal` и плановый `event.budget = guestBudget × expectedGuests`.

## Рассадка

Рассадка необязательна: по умолчанию `seating.mode` равен `off`, и банкет собирает только блюда. `GET /api/events/{eventId}` всегда возвращает объект `seating` со схемой зала, режимом, списком занятых мест `occupied` и собственным местом `mySeat`. Владелец и ресторан дополнительно получают `people` — всех гостей с их местами — и поле `seat` у каждого гостя.

`PUT /api/events/{eventId}/seating` включает рассадку и сохраняет схему целиком:

```json
{
  "mode": "choice",
  "layout": {"tables": [
    {"id":"t1","shape":"round","label":"1","x":60,"y":60,"w":120,"h":120,"rotation":0,"seats":8},
    {"id":"t2","shape":"rect","label":"Президиум","x":300,"y":60,"w":300,"h":70,"rotation":0,"seats":5,"sides":["top"]}
  ]}
}
```

Режимы: `off` — без рассадки, `choice` — гости выбирают места сами, `fixed` — места назначает организатор. Стулья не передаются: их номера и координаты вычисляются из стола, id места имеет вид `<tableId>-<n>`, нумерация идёт по часовой стрелке. Готовые шаблоны (круглые столы, П-образная, с президиумом, Т-образная, длинный стол) строит функция `generateLayout` из `shared/seating.mjs`. Сохранить схему, в которой пропадает уже занятое место, нельзя: сервер вернёт `409` и перечислит такие места.

Гость выбирает место через `PUT /api/events/{eventId}/seat` с `{"seatId":"t1-3"}`, а `{"seatId":null}` освобождает его. Если место уже занято, сервер вернёт `409`. Организатор назначает места через `PUT /api/events/{eventId}/seating/assignments` с `{"guest":"invite:...","seatId":"t2-1"}`; `guest` берётся из `seating.people[].key`. Если место занято, гости меняются местами. `POST /api/events/{eventId}/seating/auto` рассаживает всех гостей без места: сначала за столы, где уже кто-то сидит, затем за пустые. То же происходит автоматически при утверждении заказа. После утверждения рассадка фиксируется, а CSV получает колонку «Место» и отдельный блок «Стол / Место / Гость».

## Меню, КБЖУ и фото

`POST /api/restaurants/{restaurantId}/menu`, `PATCH`/`DELETE /api/restaurants/{restaurantId}/menu/{itemId}` редактируют общий каталог. Эти изменения не меняют меню уже созданного банкета. Чтобы изменить только конкретный банкет, используйте `POST /api/events/{eventId}/menu`, `PATCH`/`DELETE /api/events/{eventId}/menu/{itemId}`. Категория «Напитки» работает как любая другая; при первом запуске есть пример нескольких безалкогольных напитков.

Новая позиция содержит название, описание, категорию, цену в копейках, вес/объём, аллергены, доступность и КБЖУ **на одну порцию**:

```json
{
  "name":"Яблочный сок",
  "description":"Свежевыжатый, без сахара",
  "category":"Напитки",
  "price":29000,
  "weight":"250 мл",
  "allergens":[],
  "labels":["Мало калорий"],
  "vegetarian":true,
  "available":true,
  "nutrition":{"kcal":110,"protein":0,"fat":0,"carbs":26.5},
  "photoUrl":""
}
```

Калории — целое число; белки, жиры и углеводы — граммы с точностью до 0,1. Примеры КБЖУ в стартовом меню ориентировочные и требуют проверки рестораном. Позиции старых пользовательских каталогов могут ещё не иметь КБЖУ, пока их не обновят. Если блюдо уже выбрано, его цена, название и доступность в меню банкета заблокированы; описание, КБЖУ и фото редактируются.

`labels` — необязательный список без повторов: `Халяль`, `Много белка`, `Мало калорий`. Его можно редактировать как в каталоге, так и в меню конкретного банкета. Старые позиции без поля возвращаются с `labels: []`. Пометку «Халяль» добавляйте только после подтверждения рестораном; сервис её не вычисляет по составу автоматически.

Фото загрузите бинарным запросом `POST /api/media` с `Content-Type: image/jpeg`, `image/png` или `image/webp`, размером до 3 МиБ. Ответ `{"photoUrl":"/api/media/<имя>"}` используйте в JSON позиции. Для production абсолютный адрес фото образуется как `https://mail.lonelycraft.ru/banquet` + `photoUrl`. `GET /api/media/{fileName}` открыт для показа карточек. Файлы и SQLite хранятся в постоянном Docker-томе.

## Уведомления

`PUT /api/me/notifications` с `{"enabled":true}` включает уведомления для текущего пользователя, `false` выключает. По умолчанию они выключены. Также нужен начатый личный диалог с ботом; после `bot_stopped` отправка останавливается. Очередь отправляет организатору новости о входе и выборе гостя, гостю — напоминание до дедлайна и результат утверждения, ресторану — сообщение об утверждённом заказе. При изменении параметров банкета присоединившиеся гости получают обновление. Напоминание отменяется после сохранения выбора. Доставка через MAX может задерживаться; отправка внешнему пользователю возможна только если он включил уведомления и не остановил бота.

Административные операции из этого документа доступны и через Mini App, и через HTTP API. Сервер всегда проверяет роль, владение, телефон гостя, статус и актуальность заказа независимо от интерфейса.
