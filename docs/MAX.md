# Подключение к MAX

Интеграция опирается на официальную документацию MAX, проверенную 16 сентября 2026 года. Mini App — наш HTTPS-сайт, который открывается внутри бота. Сервер хранит заказы и проверяет подпись пользователя, а MAX передаёт контекст запуска.

## Что нужно сделать владельцу

1. Откройте [MAX для партнёров](https://business.max.ru), создайте и верифицируйте профиль организации, ИП или самозанятого. Сейчас сервисы доступны этим категориям резидентов РФ; обычному физлицу верификация недоступна. [Порядок подключения](https://dev.max.ru/docs/maxbusiness/connection).
2. Создайте бота и дождитесь модерации. Документация указывает до 48 часов по рабочим дням. Имя для публичной ссылки генерируется платформой; заранее выбирать предполагаемый username в конфигурации нельзя. [Создание бота](https://dev.max.ru/docs/chatbots/bots-create/create).
3. В разделе **Чат-боты → ⋮ → Настройки** скопируйте токен существующего бота и его username. Токен доступен после модерации. [Получение токена](https://dev.max.ru/docs/chatbots/bots-create/manage).
4. Внесите значения в серверное окружение или локальный файл `.env`, исключённый из Git. Скрипты проекта не создают аккаунты, ботов или секреты.

```dotenv
MAX_BOT_TOKEN=
MAX_BOT_USERNAME=
MAX_WEBHOOK_SECRET=
PUBLIC_URL=https://mail.lonelycraft.ru/banquet
MAX_API_URL=https://platform-api2.max.ru
```

`MAX_WEBHOOK_SECRET` задаёт владелец: 5–256 латинских букв, цифр, `_` или `-`. Это отдельный секрет проверки входящих событий. Не публикуйте ни его, ни токен в GitHub, клиентском JavaScript, логах или скриншотах. `.env.example` должен содержать только пустые поля.

5. После развёртывания HTTPS явно запустите настройку из каталога проекта на Node.js 24 или новее:

```sh
node --env-file=.env scripts/setup-max.mjs
```

Скрипт выполняет `GET /me`, проверяет соответствие username, затем `POST /subscriptions`. Он выводит только username и публичные URL. Импорт модуля, сборка, тесты и обычный запуск сервера эту подписку не создают. Не запускайте скрипт во время проверки без намерения подключить существующего бота.

6. На платформе **Чат-боты → ⋮ → Настройки** укажите URL Mini App `https://mail.lonelycraft.ru/banquet`, выберите кнопку **Открыть** и сохраните. Этот шаг выполняется владельцем в интерфейсе MAX. [Подключение Mini App](https://dev.max.ru/docs/webapps/introduction).
7. Откройте ссылку, которую напечатал скрипт, из MAX. Проверьте вход организатора, создание мероприятия, приглашение второму пользователю, выбор блюд гостем и утверждение заказа. Проверка в обычном браузере не заменяет проверку настоящих подписанных `initData` в MAX.

## API и доставка событий

Текущий API — `https://platform-api2.max.ru`; токен передаётся заголовком `Authorization: <token>` без `Bearer`. MAX требует добавить сертификат Минцифры в доверенное хранилище. Если на сервере возникает ошибка TLS, установите проверенный корневой сертификат по официальным указаниям поставщика и, при необходимости, настройте `NODE_EXTRA_CA_CERTS`; проверку TLS отключать нельзя. Общий лимит API составляет 30 запросов в секунду. [Обзор API](https://dev.max.ru/docs-api).

Вебхук доступен по `${PUBLIC_URL}/api/max/webhook`, для текущего адреса это `https://mail.lonelycraft.ru/banquet/api/max/webhook`. MAX использует HTTPS на порту 443 с полной доверенной цепочкой сертификатов. Сервер проверяет `X-Max-Bot-Api-Secret`. Неверный секрет даёт 401; отсутствие конфигурации — 503. Обработчик использует тайм-аут API 8 секунд и ограничивает размер его ответа 64 КиБ. MAX ожидает HTTP 200 не позднее 30 секунд. При недоступности вебхука восемь часов подписка автоматически снимается. [Webhook API](https://dev.max.ru/docs-api/methods/POST/subscriptions).

Бот реагирует на `bot_started` и сообщения людей в личном диалоге (`message_created`): отвечает описанием сервиса и ссылкой Mini App. Сообщения других ботов и групповые чаты игнорируются. Фоновых рассылок нет. Отправка сообщений ограничена MAX двумя сообщениями в секунду одному адресату. [Отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages).

Повтор одного события не должен отправлять повторный ответ. Backend передаёт в `createMaxBot(config, { claimUpdate })` функцию `claimUpdate(key)`, которая атомарно сохраняет уникальный ключ в БД и возвращает `true` только при первом поступлении. Храните ключи не менее семи суток. Запись выполняется **перед** API-вызовом. При неоднозначной ошибке отправки повтор подавляется: это семантика «не более одного ответа», поэтому отдельное приветствие при сетевом сбое может не дойти. Пользователь может повторно написать боту. Ошибка БД возвращает 503 до отправки, позволяя MAX повторить событие.

## Запуск, приглашения и безопасность

Клиент подключает [MAX Bridge](https://dev.max.ru/docs/webapps/bridge) через `https://st.max.ru/js/max-web-app.js` и читает `window.WebApp.initData`. Объект доступен после загрузки библиотеки без отдельной инициализации. `initDataUnsafe` подходит для предварительного отображения, но не доказывает личность пользователя.

Приглашение имеет вид `https://max.ru/<username>?startapp=<inviteToken>`. Payload содержит только `A-Z`, `a-z`, `0-9`, `_`, `-` и не превышает 512 символов. Используйте случайный непрозрачный идентификатор приглашения, не персональные данные. Значение попадает в `start_param`; доступ к мероприятию всё равно проверяет наш сервер. `?start=` запускает бота и передаёт `payload` событию `bot_started`, а `?startapp=` сразу открывает Mini App. Для обмена приглашением подходит `WebApp.shareMaxContent({text, link})`, вызванный по нажатию кнопки. [Диплинки Mini Apps](https://dev.max.ru/docs/webapps/introduction), [диплинки бота](https://dev.max.ru/docs/chatbots/bots-coding/prepare).

Сервер должен проверять исходную строку `initData`: отклонить повторяющиеся ключи, извлечь единственный `hash`, URL-декодировать значения ровно один раз, отсортировать пары по ключу и соединить `key=value` переводом строки LF. JSON-значения нельзя повторно сериализовать. Ключ подписи — бинарный результат HMAC-SHA256 от токена с ключом `WebAppData`. Этим ключом подписывается подготовленная строка, результат сравнивается с hex `hash`. Дополнительно проверяются свежесть `auth_date` (MAX рекомендует один час) и структура пользователя. Подпись не заменяет проверку роли организатора или ресторанного сотрудника. [Алгоритм валидации](https://dev.max.ru/docs/webapps/validation).
