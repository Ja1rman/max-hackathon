# Документы поставки

При каждом изменении продукта проверяйте, затронуты ли правила доступа, API, тестовые данные, Docker-запуск или ограничения. Если затронуты, обновляйте документацию в том же изменении:

- `README.md`: пользовательский сценарий, архитектура, локальный Docker-запуск, переменные и порты, интеграции, данные, ручная проверка и ограничения.
- `openapi.yaml`, `DATA-API.yaml`, `fixtures/api-checks.json`, `docs/TESTING.md`: методы, форматы, обязательные проверки, роли и повторяемый сценарий. Новую основную функцию отражайте в сценарии проверки API.
- `docs/DATA-MODEL.yaml` и `fixtures/demo.json`: схему хранения и фактический стартовый демо-набор. Демо создаётся кодом, поэтому JSON — описательный манифест, а не файл импорта.
- `Dockerfile`, `compose.yaml`, `.dockerignore`, `.env.example`: состав и воспроизводимость локального запуска; примеры переменных не должны содержать действующих секретов.

Перед завершением работы запускайте `npm run check`; при изменении API — также `npm run api:check` на доступном стенде или локальном сервере. Проверяйте, что данные тестового сценария не устарели и дата мероприятия остаётся в будущем. Если Docker-демон доступен, проверяйте `docker compose up -d --build` и `/api/v1/healthz`. Не объявляйте сборку за пять минут подтверждённой без замера времени полной сборки.
